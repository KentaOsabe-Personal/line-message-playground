# 文章判定ラボ「書き換えて比較」要件

作成日：2026年10月5日。既存の[文章判定ラボの仕様](../../.kiro/specs/text-judgment-lab/requirements.md)へ追加する要件案。正式specの更新・承認は別途行う。

## 目的

判定済みの文章を書き換え、元の文章と書き換え後の文章の判定結果を見比べる。言い回しによって「分類・感情・急ぎの要望」の判定がどう変わるかを、既存のチャット画面で確認できるようにする。

## 操作と表示

1. 判定に成功した結果に「書き換えて試す」ボタンを表示する。
2. 利用者がボタンを押すと、選んだ文章を入力欄へコピーし、比較元を表示する。入力中の文章がある場合は、置き換えてよいか利用者に確認する。
3. 利用者が文章を編集し、「比較する」を押す。書き換え後の文章だけをJevへ送り、元の文章は再判定せずに既存の結果を使う。
4. 判定に成功したら、元の文章と書き換え後の文章を、それぞれの判定結果とともに一組で表示する。「元の文章」「書き換え後」と明示し、比較結果をチャット内に残して通常の入力に戻る。

比較中は「比較をやめる」で、入力欄の文章を残したまま通常の入力に戻れる。同時に編集できる比較は一組だけとする。

| 比較する項目 | 表示内容 |
|---|---|
| 分類 | 選ばれた分類と4候補の確率 |
| 感情 | 0〜2のスコアと目盛り |
| 急ぎの要望 | 確率 |

比較する文章と結果は、広い画面では左右、スマートフォンでは上下に並べる。比較項目の順序はそろえる。応答時間・モデル・Jevの返却値も、各結果で引き続き確認できる。

## 制約と失敗時の動作

- 既存の判定APIと3つの質問を使う。比較元や履歴はJevへ送らず、各文章を独立に判定する。
- 元の文章と結果は変更しない。判定中は二重送信と比較元の切り替えを防ぐ。
- 通信失敗・タイムアウト時は、比較元と編集内容を残してエラーを表示する。利用者が再送でき、自動再送はしない。
- 1〜1,000文字の制限、認証・利用制限は既存仕様に従う。画面離脱や認証失効後に届いた応答も、既存仕様に従って破棄する。
- 比較結果はページ内のメモリだけに保持し、再読み込みや画面離脱で消去する。
- 数値の違いはモデルの判定差として示し、文章の優劣や判定理由を自動で説明しない。

## 受入条件

- 過去の判定済み文章を選び、コピー・編集・判定・比較まで同じ画面で完了できる。
- 元の文章と結果が保たれ、書き換え後の文章だけを送って判定APIを1回呼び出す。
- 元の文章と書き換え後の文章、それぞれの結果を区別でき、スマートフォンでも横にはみ出さず比較できる。
- 入力欄の文章の置き換えを断った場合は、その文章が残る。比較を中止した後は通常の送信ができる。
- 判定失敗後も同じ比較元と編集内容で再送でき、成功後の結果が正しい比較元と対応する。

## 対象外と規模

返信の必要性判定、自由な判定条件、文章の自動書き換え、3件以上の一括比較、永続保存は追加しない。

規模判定は `PASS (single-spec)`。既存specを拡張し、文章比較機能を1つ追加する。変更範囲はFrontendの比較状態の管理と表示で、外部連携は既存の判定API呼び出し1系統とする。

作業は、比較状態の管理・比較表示・境界テスト・実画面確認の4タスクを見込む。各タスクは1〜3時間単位。Backend・DBの変更やデータ移行は不要。
