# 旧版の置換成功記録を後片付けへ戻す管理修復

旧版は、置換後の旧メニューが残っていても適用操作を成功確定し、後片付けを受け付けるblockerを解放していた。通常APIのterminal遷移制約は維持し、管理コマンドだけで、active owner・provider・channel revision・現在資源・旧資源の作成元と置換操作をlock下で照合して、一件ずつ後片付け待ちへ戻す。元の成功transitionと設定を残し、成功から後片付け待ちへの修復transitionを追記する。修復自体はLINEを変更せず、削除は既存の所有権検証付きcleanupへ渡す。関係不明の資源を推測で修復せず、通常の置換確定も旧資源が残る間は後片付け待ちとする。

複数の旧資源が連鎖している場合は古い資源から修復する。前任の旧資源が残る対象は明示指定でも拒否し、後続資源が生存しているという関係証明を失わない順序で既存cleanupへ渡す。
