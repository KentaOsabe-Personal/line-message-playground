# Requirements Document

## Introduction

LINE Message Playground に、認証済み owner が同一 provider 配下の複数 Messaging API チャネルを安全に管理する専用画面を追加する。owner はチャネルの一覧、登録、更新、有効化、無効化、Webhook URL、設定状態、および接続確認結果を一か所で扱える。アクセストークンとチャネルシークレットは write-only の資格情報ペアとして扱い、保存済みの平文または暗号文を画面、応答、ログへ露出させない。

## 用語

- **owner**: LINE Message Playground の管理操作を実行できる、事前許可された認証済み利用者
- **資格情報ペア**: 1つの Messaging API チャネルに対応するチャネルアクセストークンとチャネルシークレットの組
- **接続確認**: 保存済みアクセストークンを使った送信を伴わない LINE への疎通確認。チャネルシークレットまたは Webhook の疎通を保証するものではない
- **参照中チャネル**: 配信先、配信記録、Webhook または interaction の記録など、保持すべき既存データから識別されるチャネル

## 境界コンテキスト

- **対象範囲**: owner の LINE identity と同一 provider 配下にあるチャネルの一覧・詳細、登録、非秘密メタデータ更新、有効化・無効化、write-only 資格情報ペア置換、設定済み状態と更新日時、チャネル別 Webhook URL の表示・コピー、送信を伴わない接続確認、参照整合性を守る削除制約、画面の読み込み・空・エラー・処理中状態
- **対象外**: 異なる provider のチャネル管理、暗号化キーの管理・ローテーション画面、保存済み資格情報の表示・コピー・エクスポート、複数管理者または RBAC、LINE Developers コンソールの自動変更、LINE 公式アカウントや資格情報の発行・失効、配信先管理、メッセージ配信、利用量・課金管理、接続確認履歴、定期的な自動監視
- **隣接する前提**: `line-channel-foundation` がチャネル、暗号化資格情報、および用途別の安全な資格情報利用を提供し、`line-account-linking` が owner セッションを提供する。`line-webhook-ingress`、`line-friendship-sync`、`line-webhook-command-dispatch`、`linked-recipient-delivery` はチャネルの有効状態と既存記録を利用する。本仕様はこれらの認証、Webhook 受付、配信先状態、配信処理、または監査記録を再実装しない。

## 要求事項

### Requirement 1: owner 限定の管理アクセス

**目的:** owner として、自分だけがチャネル設定と資格情報を管理したい。これにより、未認証者や許可されていない利用者による参照・変更を防げる。

#### 受入基準

1. While 有効な owner セッションが存在する, the LINEチャネル管理機能 shall チャネルの一覧、詳細、登録、更新、状態変更、削除、および接続確認を当該 owner に提供する
2. If owner セッションが存在しない、無効、期限切れ、または全連携解除処理中である, the LINEチャネル管理機能 shall チャネル情報と操作結果を提供せず、再認証または利用不可を示す安全な状態を返す
3. When チャネルまたは資格情報の状態を変更する要求を受け付ける, the LINEチャネル管理機能 shall 正規のアプリ origin から owner が意図して実行した要求であることを確認する
4. If 認証または状態変更要求の保護を確認できない, the LINEチャネル管理機能 shall 対象チャネルと他のチャネルへ変更を加えない
5. If 操作中に owner セッションが失効する, the LINEチャネル管理機能 shall 未完了の変更を成功として表示せず、再認証が必要であることを示す
6. If 一覧または詳細の認証確認後に owner セッションが失効する、または全連携解除が開始される, the LINEチャネル管理機能 shall 当該取得を owner 状態変更より前または後のいずれかへ一貫して収束させ、状態変更後の取得としてチャネル情報を返さない

### Requirement 2: チャネル一覧・詳細と安全な設定状態

**目的:** owner として、登録済みチャネルの識別情報、状態、設定状況を秘密値なしで把握したい。これにより、複数の LINE 公式アカウントを取り違えずに管理できる。

#### 受入基準

1. When owner がチャネル一覧を開く, the LINEチャネル管理機能 shall 有効および無効な全登録チャネルを区別して表示する
2. When チャネルの一覧または詳細を表示する, the LINEチャネル管理機能 shall 運用者向け名称、不透明な公開識別子、Messaging API チャネル ID、bot user ID、provider ID、有効状態、作成日時、および更新日時を表示する
3. When チャネルの資格情報ペアが完全に保存されている, the LINEチャネル管理機能 shall 資格情報を「設定済み」として秘密値なしで表示する
4. If チャネルの資格情報ペアが完全に保存されていない, the LINEチャネル管理機能 shall 資格情報を「設定済み」と表示せず、設定の修復が必要な状態として示す
5. The LINEチャネル管理機能 shall 平文資格情報、暗号化された資格情報、暗号化キー、または資格情報の一部を一覧、詳細、応答、画面要素、もしくはコピー対象へ含めない
6. If 指定されたチャネルが存在しない、または削除済みである, the LINEチャネル管理機能 shall 他のチャネル情報を代わりに表示せず、対象不在を示す安全な状態を返す

### Requirement 3: 完全なチャネル登録

**目的:** owner として、チャネル識別情報と完全な資格情報ペアを一度に登録したい。これにより、不完全または取り違えた設定を運用へ持ち込まずに済む。

#### 受入基準

1. When owner が新しいチャネルを登録する, the LINEチャネル管理機能 shall 運用者向け名称、Messaging API チャネル ID、bot user ID、provider ID、アクセストークン、チャネルシークレット、および初期有効状態を受け付ける
2. When 有効な登録内容を受け付ける, the LINEチャネル管理機能 shall 一意で不透明な公開識別子を発行し、チャネルと資格情報ペアを一つの完了結果として保存する
3. If 運用者向け名称が空白または 255 文字を超える, the LINEチャネル管理機能 shall チャネルを登録せず対象項目の修正を求める
4. If Messaging API チャネル ID または provider ID が 1〜64 桁の数字でない, the LINEチャネル管理機能 shall チャネルを登録せず対象項目の修正を求める
5. If bot user ID が `U` に続く 32 桁の小文字 16 進数でない, the LINEチャネル管理機能 shall チャネルを登録せず対象項目の修正を求める
6. If 資格情報ペアの一方が空、空白のみ、欠落、または各 16 KiB を超える, the LINEチャネル管理機能 shall チャネルも資格情報も保存せず対象項目の修正を求める
7. If Messaging API チャネル ID または bot user ID が既存チャネルと重複する, the LINEチャネル管理機能 shall 既存チャネルを変更せず、重複を示す安全なエラーを返す
8. If チャネルまたは資格情報ペアを完全に保存できない, the LINEチャネル管理機能 shall 登録を部分的に完了せず、再試行可能性を区別した安全なエラーを返す
9. If 登録する provider ID が認証済み owner の LINE identity の provider ID と一致しない, the LINEチャネル管理機能 shall チャネルと資格情報を保存せず、異なる provider は管理対象外であることを示す

### Requirement 4: 非秘密メタデータ更新と write-only 資格情報置換

**目的:** owner として、既存の秘密値を読み戻さずにチャネル情報と資格情報を更新したい。これにより、設定変更時の秘密漏えいと部分更新を防げる。

#### 受入基準

1. When owner が登録済みチャネルの編集画面を開く, the LINEチャネル管理機能 shall 保存済みの非秘密メタデータを表示し、アクセストークンとチャネルシークレットの入力欄を空で表示する
2. When owner が運用者向け名称、Messaging API チャネル ID、または bot user ID の有効な変更を送信する, the LINEチャネル管理機能 shall 指定された項目だけを更新し、provider ID と指定されていない項目を維持する
3. If owner が登録済みの provider ID を別の値へ変更しようとする, the LINEチャネル管理機能 shall 更新を拒否し、チャネルを再登録すべき変更であることを示す
4. When アクセストークンとチャネルシークレットの両方が空欄で更新される, the LINEチャネル管理機能 shall 保存済み資格情報ペアを変更しない
5. When 新しいアクセストークンと新しいチャネルシークレットの両方が有効な値で更新される, the LINEチャネル管理機能 shall 保存済み資格情報ペアを完全な新しいペアで置換する
6. If アクセストークンとチャネルシークレットの一方だけに値が入力される, the LINEチャネル管理機能 shall 資格情報と非秘密メタデータのいずれも更新せず、完全なペアの入力を求める
7. If 更新内容の検証、資格情報の保護、または保存のいずれかに失敗する, the LINEチャネル管理機能 shall 更新前のメタデータ、有効状態、および資格情報ペアを維持する
8. When 更新が完了する, the LINEチャネル管理機能 shall 更新後の非秘密情報、設定済み状態、および更新日時だけを返す
9. The LINEチャネル管理機能 shall 保存済み資格情報を編集欄の初期値、placeholder、応答、エラー、または再表示用データとして返さない
10. If provider ID が未設定の既存チャネルへ provider ID を補完する, the LINEチャネル管理機能 shall 認証済み owner の LINE identity と一致する provider ID だけを受け付け、一致しない場合は非秘密メタデータ、資格情報、および有効状態を変更しない

### Requirement 5: 有効化・無効化と履歴保全

**目的:** owner として、チャネルの記録を失わずに新しい利用を停止または再開したい。これにより、学習用チャネルの切り替えと既存履歴の追跡を両立できる。

#### 受入基準

1. When owner が有効なチャネルの無効化を確認する, the LINEチャネル管理機能 shall チャネル識別情報、資格情報ペア、および既存記録を保持したまま当該チャネルを無効にする
2. While チャネルが無効である, the LINEチャネル管理機能 shall 当該チャネルが新しい配信、配信先登録、または Webhook 受付に利用できない状態であることを表示する
3. When owner が無効なチャネルの有効化を要求する, the LINEチャネル管理機能 shall 保存済み資格情報ペアが完全かつ安全に利用可能である場合だけ同じ公開識別子で有効状態へ戻す
4. If 保存済み資格情報ペアが欠損、破損、または安全に利用できない, the LINEチャネル管理機能 shall チャネルを有効化せず、完全な資格情報ペアによる修復を求める
5. When owner が完全な新しい資格情報ペアによる修復と有効化を同時に要求する, the LINEチャネル管理機能 shall 両方を一つの変更として完了するか、どちらも変更しない
6. If 状態変更の対象が存在しない、または現在状態と要求が競合する, the LINEチャネル管理機能 shall 他のチャネルへ変更を加えず、最新状態の再取得を促す安全な結果を返す

### Requirement 6: チャネル別 Webhook URL の表示とコピー

**目的:** owner として、各チャネルに対応する Webhook URL を取り違えずに確認・コピーしたい。これにより、LINE Developers コンソールへ手作業で正しい受付先を設定できる。

#### 受入基準

1. When チャネルの一覧または詳細を表示する, the LINEチャネル管理機能 shall 検証済みの公開 origin と当該チャネルの不透明な公開識別子に対応する完全な Webhook URL を表示する
2. When owner が Webhook URL のコピーを実行する, the LINEチャネル管理機能 shall 画面に表示した URL と同一の値をコピーし、成功または失敗を通知する
3. While チャネルが無効である, the LINEチャネル管理機能 shall Webhook URL と無効状態を併記し、受付可能または接続済みであると表示しない
4. The LINEチャネル管理機能 shall Webhook URL に資格情報、内部連番、owner の LINE ユーザー ID、またはセッション情報を含めない
5. The LINEチャネル管理機能 shall Webhook URL の表示またはコピーを理由に LINE Developers コンソールの設定を自動変更しない

### Requirement 7: 秘密値を返さない接続確認

**目的:** owner として、保存済み設定で対象チャネルへ安全に接続できるか確認したい。これにより、配信を行う前に資格情報やチャネルの取り違えを発見できる。

#### 受入基準

1. When owner が登録済みチャネルの接続確認を開始する, the LINEチャネル管理機能 shall メッセージ送信その他の変更を LINE 上で発生させず、保存済みアクセストークンによる疎通を一回確認する
2. When LINE が認証した bot user ID と保存済み bot user ID が一致する, the LINEチャネル管理機能 shall 対象チャネルを `connected` と分類し、確認日時を表示する
3. If 保存済み資格情報を安全に利用できない, the LINEチャネル管理機能 shall LINE へ接続せず `credential_unavailable` と分類する
4. If LINE がアクセストークンを拒否する, the LINEチャネル管理機能 shall `authentication_failed` と分類する
5. If LINE が認証した bot user ID と保存済み bot user ID が一致しない, the LINEチャネル管理機能 shall 成功として扱わず `identity_mismatch` と分類する
6. If LINE が利用制限を返す, the LINEチャネル管理機能 shall `rate_limited` と分類し、自動再試行しない
7. If LINE への接続がタイムアウト、利用不能、または結果不確定となる, the LINEチャネル管理機能 shall 成功または認証失敗と推測せず `line_unavailable` と分類する
8. The LINEチャネル管理機能 shall 接続確認結果へアクセストークン、チャネルシークレット、暗号文、LINE の生応答、応答ヘッダー、または外部リクエスト ID を含めない
9. The LINEチャネル管理機能 shall 接続確認の成功をチャネルシークレットの正当性、Webhook の疎通、メッセージ配信成功、または端末到達の確認として表示しない
10. If 接続確認の開始後から結果確定までに対象チャネルの bot user ID、資格情報、または更新 revision が変更される, the LINEチャネル管理機能 shall 取得済みの LINE 結果を現在設定の確認結果として表示せず、最新状態の再取得を求める

### Requirement 8: 参照整合性を守るチャネル削除

**目的:** owner として、誤って作成した未使用チャネルだけを削除し、利用履歴のあるチャネルは無効化へ収束させたい。これにより、配信先や監査記録の追跡可能性を失わずに済む。

#### 受入基準

1. When owner がチャネルの物理削除を開始する, the LINEチャネル管理機能 shall 対象の運用者向け名称、不透明な公開識別子、現在状態、および削除が取り消せないことを確認させる
2. When owner が削除を確認する, the LINEチャネル管理機能 shall 削除直前に当該チャネルが参照中でないことを再確認する
3. If チャネルが配信先、配信記録、Webhook 記録、interaction 記録、または保持すべき他の履歴から参照されている, the LINEチャネル管理機能 shall チャネルと資格情報を削除せず、無効化を案内する
4. If 削除確認後に当該チャネルへの新しい参照が作成される, the LINEチャネル管理機能 shall 削除を部分的に完了せず、参照中であることを示す
5. When owner が参照されていないチャネルの削除を確認する, the LINEチャネル管理機能 shall 対象チャネルと保存済み資格情報ペアだけを削除し、他のチャネルを変更しない
6. When チャネル削除が完了する, the LINEチャネル管理機能 shall 削除した秘密値または暗号文を返さず、対象の非秘密識別情報と完了結果だけを表示する
7. If チャネル削除を完全に完了できない, the LINEチャネル管理機能 shall チャネルまたは資格情報だけが残る部分削除を成功として表示しない

### Requirement 9: 安全で回復可能な画面状態

**目的:** owner として、読み込み中、入力エラー、通信失敗、処理中を区別し、安全に操作をやり直したい。これにより、二重操作や秘密値の残留を避けながら管理を継続できる。

#### 受入基準

1. While チャネル一覧または詳細を取得中である, the LINEチャネル管理機能 shall 読み込み中であることを表示し、未取得データを最新状態として表示しない
2. When 登録済みチャネルが一件もない一覧を取得する, the LINEチャネル管理機能 shall 空状態と新規登録への導線を表示する
3. If 一覧または詳細を取得できない, the LINEチャネル管理機能 shall 以前のデータを最新として断定せず、安全なエラーと再取得手段を表示する
4. While 登録、更新、状態変更、削除、または接続確認を処理中である, the LINEチャネル管理機能 shall 対象操作の処理中状態を表示し、同じ操作の重複送信を許可しない
5. When 入力検証に失敗する, the LINEチャネル管理機能 shall 秘密値を引用せず、修正可能な非秘密項目または資格情報ペアの入力状態を示す
6. When 状態変更が成功する, the LINEチャネル管理機能 shall 最新の非秘密チャネル状態を表示し、成功した操作を明示する
7. If 状態変更の結果が不明または通信失敗である, the LINEチャネル管理機能 shall 成功と推測せず、最新状態を再取得してから再操作するよう案内する
8. When 資格情報を含む要求が完了または失敗する, the LINEチャネル管理機能 shall 資格情報入力欄を空に戻し、再試行時は完全な資格情報ペアの再入力を求める
9. The LINEチャネル管理機能 shall 資格情報をブラウザの永続ストレージ、URL、画面要素の属性、操作履歴、通常ログ、エラー報告、または状態スナップショットへ保持しない
10. The LINEチャネル管理機能 shall 失敗または結果不明となった状態変更や接続確認を owner の明示操作なしに自動再実行しない
