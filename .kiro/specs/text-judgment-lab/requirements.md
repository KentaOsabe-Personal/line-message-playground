# 要件：自由文の文章判定ラボ

## Spec Size Assessment

PASS (single-spec)。2026-10-04にユーザーが、自由文をJevへ送り分類・感情・急ぎの要望をチャットに返す最小構成への全面改修を承認。旧通知相談の要件・設計・タスクを本仕様で置換する。

責任境界は既存のFrontendと判定API。提供成果は自由文判定チャット1つ、外部ワークフローは既存認証下のJev呼出し1つ。1〜3時間単位で5タスク（契約・質問とAPI、チャット、旧処理整理、境界テスト、実画面確認）。DB・新サービス・業務操作は追加しない。Requirements・Design・Tasksの各段階とも同じ範囲でPASS。

## 受入条件

1. 既存LINEミニアプリ入口・本人認証でチャットを開く。テーマ選択や予約・通知相談の業務操作はない。
2. ユーザーは1〜1,000文字の任意の文章を送れる。Jevには今回の文章だけを送り、会話履歴・identityを送らない。
3. 一度のJev呼出しで、Choice（質問・依頼・報告・その他）、Score（否定的0・中立1・肯定的2）、Noul（早い対応の要望）を判定する。
4. 入力と結果をチャットに残す。分類と4候補の確率、感情の数値と目盛り、急ぎの確率、Jev通信の実測時間を表示する。モデルと元の返却値も確認できる。
5. 採用・保留への変換、アプリ独自の回答生成、業務上の判断はしない。数値の丸めは表示だけに限る。確率やconfidenceを正解率と説明しない。
6. 入力欄と送信ボタンをわかりやすく配置し、モバイルで横にはみ出さない。Enterは改行とし、送信はボタンで行う。
7. 判定中は二重送信を防ぐ。エラー・タイムアウト・認証失効は結果と区別し、入力を復元する。自動再送しない。画面離脱や失効後の後着結果は表示しない。
8. 入力は外部AIへ送られる旨を短く表示する。既存の認証、Origin照合、制限、no-store、秘密情報保護を保持する。チャットはページ内のメモリだけに保持する。

## 対象外

LLM比較、費用集計、実験テーマ、例文の自動実行、永続履歴、予約操作、LINE送信、業務会話、動的な質問設定。
