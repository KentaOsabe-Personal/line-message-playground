# Brief: text-judgment-lab-comparison

## Problem

文章判定ラボの利用者は、言い回しを変えたときにJevの分類・感情・急ぎの要望の判定がどう変わるかを、現在のチャット画面で見比べにくい。

## Current State

自由文を1件ずつ独立に判定し、結果をチャットに残す。判定済みの文章を入力欄へ戻す操作と、元の結果・書き換え後の結果を対応付けて表示する機能はない。既存の`text-judgment-lab`は比較を対象外として完了済み。

## Desired Outcome

利用者が過去の判定済み文章を選び、同じ画面で書き換えて判定し、元の文章と結果を書き換え後の文章と結果に並べて比較できる。元の結果は再判定せず、比較終了後は通常の入力へ戻れる。

## Approach

既存の判定APIと固定3質問を再利用する。Frontendで比較元の文章・結果の固定値、編集中の文章、送信中・失敗・成功を一組として管理し、既存の結果表示を比較用にも使う。変更後の文章だけを独立に送信する。

| 方針 | 範囲と利点 | 欠点・判断 |
|---|---|---|
| Frontend内で比較する（選択） | 既存APIと表示部品を再利用し、1画面・1成果に収める | 比較元と送信状態の対応付けをFrontendで慎重に扱う |
| 比較専用APIを追加する | サーバー側で比較関係を扱える | 元の結果の再送または保存が必要になり、今回のページ内比較には契約が増える |
| 履歴画面で比較する | 多数の結果を後から選べる | 永続履歴と別画面が必要で、今回の要件を超える |

追加ライブラリは不要。既存の通常送信処理をそのまま流用すると比較結果の重複や比較元の取り違えが起こり得るため、比較の送信経路は明示的に区別する。

## Scope

- In: 判定成功結果からの比較開始、入力中の文章を置き換える確認、比較元の固定、比較の中止、書き換え後だけの判定、成功時の対表示と通常入力への復帰、失敗時の編集内容保持と手動再送、広い画面・スマートフォンでの表示、境界テストと実画面確認。
- Out: 返信の必要性判定、自由な判定条件、文章の自動書き換え、3件以上の一括比較、永続履歴、文章の優劣や判定理由の自動説明、Backend・DB・API契約の変更。

## Boundary Candidates

Frontendの比較状態と送信制御、比較表示と入力操作、既存判定APIへの接続と認証状態の扱い。独立して提供する成果は文章比較1つ。外部ワークフローは既存のJev判定1系統だけ。

## Out of Boundary

本人認証、1〜1,000文字の入力契約、利用制限、固定3質問、Jev通信と応答検証は既存の`text-judgment-lab`が所有する。比較元や履歴はJevへ送らない。

## Upstream / Downstream

Upstream: 完了済みの`text-judgment-lab`の画面・判定API・認証契約。Downstream: 文章判定ラボのチャット内で比較結果を閲覧する利用者。別の機能への公開契約は設けない。

## Existing Spec Touchpoints

- Extends: `text-judgment-lab`の利用者体験を新規specで拡張する。既存specの完了・承認履歴は変更せず、比較を対象外とした当時の記述は元の実装範囲として扱う。既存要件で対象外の「LLM比較」は異なるモデル間の比較であり、ここでは同じJevによる2文章の判定を比べる。
- Adjacent: `line-account-linking`の本人認証、`app-screen-separation`の画面寿命とroute境界。

## Spec Size Assessment

- Verdict: PASS (single-spec)
- Projected executable tasks: 4〜6件、各1〜3時間。比較状態・入力操作、比較表示、送信・失敗・失効の境界テスト、レスポンシブ表示と実画面確認、必要な統合調整を含む。
- Independent responsibility seams: 2（比較状態と送信制御、比較表示と入力操作）。どちらも同じ文章比較の成果として一緒に提供する。
- Rationale: 40件基準を下回り、独立した外部状態機械・補償フロー、上流基盤、別rollout、反復する境界横断統合がない。既存APIを1回呼ぶFrontendの垂直スライスとして、単一specで要件・設計・タスクをreviewできる。

## Constraints

- 判定元の文章と結果は変更しない。判定中は二重送信と比較元の切り替えを防ぐ。
- 通信失敗・タイムアウト時は比較元と編集内容を保持し、自動再送しない。画面離脱・認証失効後の応答は破棄する。
- 同時に編集中の比較は一組だけ。比較結果はページ内メモリに限り、再読み込み・画面離脱で消去する。
- 分類と4候補の確率、感情の0〜2スコアと目盛り、急ぎの確率を同じ順序で示し、応答時間・モデル・Jev返却値も双方で確認できる。
- 左右比較はチャット列の全幅を使い、狭い画面でも二列を維持する。余白と判定項目の配置を調整して横はみ出しを防ぐ。
- 数値はモデルの判定差として扱い、文章の優劣や判定理由を推測しない。
- 要件の詳細と受入条件は[要件資料](../../../docs/requirements/TEXT_JUDGMENT_LAB_COMPARISON_REQUIREMENTS.md)を入力として、次のRequirements工程で正式化する。
