# 実装計画

## 実行前提と所有範囲

- 各実行タスクは1〜3時間を想定する。B1はLabStateとuseTextJudgmentLab、B2はTextJudgmentLab・TextJudgmentResultとラボCSS、B3はTextJudgmentLabAuthGateを所有する。具体的な対象ファイルはdesign.mdのFile Structure Planに従う。
- 既存Docker Compose、固定済み依存、Vitest・jsdom、v3 fixtureを利用する。新規runtime・SDK・環境変数・migrationは不要。既存API・DTO・Page・共通型は変更しない。永続データ移行も不要。
- Stateとhookは同じ担当が順番に更新する。共有するUI統合テストは2→4→5.1→5.2の順で引き継ぎ、同時編集しない。3だけは1.2完了後、2と並行でき、Gateと専用認証テストに限定する。
- すべての検証を必須とする。テスト定義直前に日本語の「テストケース:」「期待値:」を記載する。本文・返却値・tokenをconsoleや新規監査へ記録しない。

- [x] 1. 比較元と送信内容を固定する純粋な状態遷移を作る
- [x] 1.1 成功結果の選択、入力置換、比較中止を実装する
  - 通常履歴と比較履歴、編集中と判定待ちを区別し、設計のローカル状態契約を用意する。React・通信・時計・tokenへの依存を持たせない。
  - 通常成功結果と比較済みの両側を選択でき、未完了・失敗・不正参照を無変更として扱う。
  - 比較元を独立した深いreadonly snapshotへコピーする。元オブジェクトや編集中の文章を変更しても保存済み文章・結果が変化しないことを単体テストで確認する。
  - 空白だけを含む非空入力は承認時だけ入力と比較元を同時置換し、拒否時は両方を保持する。選び直しで旧エラーを解除し、中止で入力を残して比較元とエラーを解除する。
  - _Boundary: LabState_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.1, 2.2, 2.4_

- [x] 1.2 判定開始、成功、失敗の遷移を実装する
  - 入力全体をUnicode code pointで数え、trim後が非空かつ1,000文字以下のときだけ開始する。送信文章と、空白・改行を含む復元用入力を分けて固定し、UIと同じ入力判定を利用できるようにする。
  - 通常送信は開始時に履歴を一件追加して完了時に更新し、比較は成功時だけ一組を追加する。成功で入力と選択を空にし、比較失敗で開始時の入力と比較元を復元する。
  - 判定待ち中の編集・選択・中止・追加送信、古いIDの完了を無変更とし、同一文章の再判定は許可する。
  - 文字数境界、失敗後の修正と手動再送、成功の重複通知、旧完了による新しい比較の上書きがないことを単体テストで確認する。
  - _Boundary: LabState_
  - _Requirements: 2.1, 3.2, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 5.1, 5.3, 5.6_

- [x] 2. 状態遷移へ既存の送信と通信寿命を接続する
- [x] 2.1 有効な入力を一回だけ送る制御へ切り替える
  - 表示データの正本を純粋状態へ統一し、設計の操作契約に従って編集・比較元選択・中止・送信を提供する。
  - 送信直前に利用資格と有効なID tokenを確認し、非許可時は編集・選択・中止も拒否する。tokenは通信呼出しの局所変数だけで扱う。
  - 同期的な実行guardを設け、React再描画前の連打でも判定が一回だけになる。比較元の再判定は行わず、既存v3契約へ書き換え後のtrim済み文章だけを渡す。
  - 既存Vitest上のhook用ハーネスで、無効入力・非許可では通信せず、開始時snapshotと一回のAPI呼出しが対応することを確認する。画面側の新契約への接続は4.2で行う。
  - _Depends: 1.2_
  - _Boundary: useTextJudgmentLab_
  - _Requirements: 2.1, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 5.4, 5.5_

- [x] 2.2 失敗復元と無効になった応答の破棄を実装する
  - 単調増加ID、abort、15秒timer、開始時snapshotで通信寿命を管理し、完了時にもjob同一性・画面存続・現在の許可・token期限・経過時間を検査する。
  - timeoutと資格喪失ではjob無効化、timer解除、abortを先に確定してから失敗遷移へ渡す。unmountは状態更新せず無効化と後片付けだけを行う。
  - 通信失敗、不正応答、5xx、429を安全な既存案内へ変換し、401はauth_expired、403・503等は既存契約に従うaccess_unavailableとして認証案内へ接続する。
  - hookの検証で入力と比較元の復元、自動再送なし、abortを無視する後着の無効化を確認する。timer通知が遅れても開始から15秒以上の成功を採用しない。
  - _Boundary: useTextJudgmentLab_
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7_

- [ ] 3. (P) 初回許可後の認証変化でも画面を読取専用で保持する
  - 許可履歴がある場合はdenied・確認中・失効・確認不可でも子の位置とkeyを保ち、初回未許可では子をmountしない。
  - 非許可時は既存の認証案内へ読取専用の説明を加え、認証方式・許可条件・LIFF呼出しを変更しない。
  - 専用認証テストで初回拒否と許可後拒否を区別し、子のmountが維持され、再許可だけで処理を自動実行しないことを確認する。比較データをGateへ渡さない。
  - _Depends: 1.2_
  - _Boundary: TextJudgmentLabAuthGate_
  - _Requirements: 5.4, 5.5, 5.7_

- [ ] 4. 共通結果表示と比較操作を画面へ組み込む
- [ ] 4.1 通常と比較で再利用する判定表示を抽出する
  - 既存結果表示を共通化し、分類と4候補確率、感情の0〜2のスコアと目盛り、急ぎの確率の順序を維持する。
  - 確率は小数第1位の百分率、感情は小数第2位、時間は整数msで表示する。モデルと時間を結果ごとに表示し、詳細には検証済み応答全体の未丸めJSONを表示する。
  - モデルの判定である旨を示し、正解率・文章の優劣・自動の理由説明を加えない。deep readonlyな結果を受け取り、元データの値を書き換えない。
  - 異なるfixture値を用いた表示検証で、数値の順序と丸め、metadata、詳細の元値を確認する。
  - _Depends: 1.1, 2.2, 3_
  - _Boundary: TextJudgmentResult, TextJudgmentLab（B2の表示抽出）_
  - _Requirements: 4.4, 4.5, 4.6, 4.7_

- [ ] 4.2 比較元の選択から成功・中止までの画面を統合する
  - 2の操作契約へ画面を接続し、通常履歴と比較履歴を描画する。成功結果だけに比較開始操作を提供し、比較済みの両側からも再比較できるようにする。
  - 入力置換は標準confirmのtrueだけで確定し、拒否・抑止時は変更しない。確認文に本文や返却値を入れず、確定後は入力、拒否後は起点の操作へfocusを戻す。
  - 比較元をcomposerの上で常時確認でき、編集中は比較・中止、待機中は判定中表示と送信時入力の読取専用表示に切り替える。待機中および非許可時はすべての変更操作を止める。
  - 成功した一組をチャットへ一度だけ追加し、通常入力へ戻す。中止は編集内容を残し、成功・中止後は入力へfocusを戻す。失効時は既存認証案内を妨げない。
  - EnterとIMEの入力で送信せず、状態を文字と既存semantic roleで示す。外部AI送信・個人情報と秘密情報を入力しない注意書きを同じcomposerに常時表示する。
  - _Depends: 1.2, 2.2, 3, 4.1_
  - _Boundary: TextJudgmentLab, useTextJudgmentLab（B2とB1の画面接続統合）_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 2.5, 3.2, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 6.4, 6.5, 6.6_

- [ ] 4.3 比較結果の全幅レイアウトとキーボード表示を整える
  - 比較を既存吹き出しの幅制限から外した独立articleとし、元と書き換え後を見出し付きsectionとしてチャット列の全幅で表示する。
  - 768px以上は均等二列、未満は元・書き換え後のDOM順で一列にする。列とカードの最小幅を抑え、文章の改行を保ち、長いモデル名・JSONも折り返す。
  - ラボ領域に限定したCSSと既存theme tokenを使い、全操作のfocus-visibleを表示する。比較開始操作と詳細summaryを各側の見出しへ関連付け、縦スクロールするJSONにもキーボードで到達できるようにする。
  - 画面幅を変えても文章と結果の対応が保たれ、状態が色だけに依存しない表示になることを確認する。実ブラウザの境界幅・実focusの検証は6で行う。
  - _Boundary: TextJudgmentLab, TextJudgmentResult（B2のレイアウトと操作表示）_
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5_

- [ ] 5. 操作・通信・認証を横断する必須統合テストを追加する
- [ ] 5.1 比較の一連の操作と既存HTTP契約を検証する
  - 通常成功から比較選択、空白を含む入力の置換承認・拒否・抑止、選び直し、中止後の通常送信、同一文章の再判定を画面から検証する。
  - 文字数0・1・1,000・1,001と補助平面文字、空白・改行、Enter・IME、同一イベント内連打、通常待機中と比較待機中の全変更禁止を確認する。
  - API引数を完全一致で検査し、比較一回でv3と書き換え後文章だけを一回送ること、比較元・履歴・identityを送らないことを確認する。既存APIテストでBearer、cookie omit、cache no-store、redirect errorの契約を回帰確認する。
  - 異なる両側結果の数値・モデル・時間・未丸めJSONと見出し、履歴の重複なし、成功後の空入力、両側からの再比較、focusと常時注意書きを確認する。
  - _Depends: 2.2, 4.3_
  - _Boundary: TextJudgmentLab, TextJudgmentResult, useTextJudgmentLab, LabState（操作・通信統合検証）_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 6.4, 6.5, 6.6_

- [ ] 5.2 失敗と古い応答が新しい比較を壊さないことを検証する
  - network、429、不正応答、5xx、401、403、503ごとに、安全な案内と送信時の空白・改行を含む入力、比較元が保持されることを確認する。
  - 失敗後の修正と手動再送が保持した比較元へ対応し、失敗・再許可だけでは再送しないことを確認する。
  - 偽timerと遅延Promiseで15秒到達、timer通知より前の期限後完了、abortを無視する旧成功・失敗を再現する。新しい比較の入力・履歴・通信を旧応答が変更しないことを確認する。
  - 完了直前のtoken期限切れや資格喪失でも成功を採用せず、無効化・timer解除・abort後に読取専用となることを確認する。
  - _Depends: 2.2, 4.2, 5.1_
  - _Boundary: TextJudgmentLab, useTextJudgmentLab, LabState（失敗・通信競合統合検証）_

- [ ] 5.3 実認証ゲートと画面寿命を統合検証する
  - Pageと実AuthGateを合成した専用テストで、期限切れ、visible復帰時の再確認、確認不可、許可後denied、再許可を再現する。
  - 入力・比較元・表示済み結果が画面存続中に保持され、非許可中は変更操作と通信が止まり、再許可後も明示送信を待つことを確認する。
  - 初回deniedでは内容が未mountであること、待機中のunmountでtimer解除とabortが行われ、後着が破棄されることを確認する。
  - 再mountでは空の通常入力に戻り、URL・storage・共有storeから復元しないことを確認する。再認証が文書遷移する場合も画面離脱として扱う。
  - _Depends: 2.2, 3, 4.2_
  - _Boundary: TextJudgmentLabPage, TextJudgmentLabAuthGate, useTextJudgmentLab（B1・B3の寿命統合検証）_

  - キーボードだけで置換拒否・承認、編集、中止、再比較、送信、詳細表示まで操作し、focus、改行、状態の文字案内、注意書きを確認する。LINE内ブラウザでも標準confirmの操作を検証する。
